Audit pass: verified against real toolchains, and one 42x fix

The three things that previously "needed the machine" were done here instead,
by installing the actual toolchains in the sandbox rather than reading the code
harder.

Rust (cargo check + clippy, 1.95): the workspace type-checks, graphvis-ffi
included - the Mutex/catch_unwind rewrite was the highest-risk unbuilt change
and it is correct. Clippy went from 12 warnings to zero. Two of those were
Linux-only artefacts of Windows-gated code: NonZeroIsize, Context, DeviceExt
and from_surface are all used solely from from_win32, so they are now behind
the same cfg rather than deleted, which would have broken the shipping build.
Verified by flipping the cfg and compiling the Windows branches: also clean.
clippy::large_enum_variant on Command is annotated rather than "fixed" - the
enum is never stored, so boxing it would trade a stack copy for a heap
allocation on every user action.

QML (qmllint 6.11.2): 201 warnings to 3, and the 3 are GraphVis.VTK not being
present in the sandbox. Real defects found and fixed:

  - PanelScroll aliased `spacing`, which is FINAL on QQuickControl. Seven
    panels set it, so all seven were setting the Control's spacing and none of
    them had the column spacing they appear to ask for. Renamed contentSpacing.
  - ThemePicker used the Window attached property without importing
    QtQuick.Window, so root.Window was undefined and the popup's height
    binding raised a TypeError instead of falling back to 800.
  - LiteratureWorkspace's annotation list read a ListModel role called "text",
    which is also Label.text. Renamed to "body" and declared required.
  - The command palette called clicked() on itemAtIndex(0), which is null for
    an item the view has not realised - exactly the case when Enter is pressed
    straight after typing. It runs the action from the model now.
  - Seven items set height inside a Layout, which Qt documents as undefined.
  - pragma ComponentBehavior: Bound across the delegate-using files, with
    required properties declared, so ids resolve at compile time instead of
    walking out of the component at every evaluation.

C++ (clang -Wall -Wextra -Wrange-loop-analysis, real Qt and Arrow headers):
zero warnings. Five `for (const QJsonValue& v : array)` bound a reference to a
per-iteration temporary; one unused variable; one unused lambda capture.

PowerShell: all 21 scripts parse, with zero PowerShell 5.1 compatibility
warnings - checked with the project's own Check-Scripts.ps1 under pwsh 7.

Measured performance work, on real fixtures:

  - ArrowTable::load called reserve(size + batchRows) inside the batch loop.
    An exact capacity request per batch reallocates and copies the whole
    accumulated column every time - quadratic in batch count. A 481 MB file
    written in 300 batches took 13.8 s to load; the same data in one batch took
    76 ms. Reserving once from a first-batch estimate: 13,618 ms -> 319 ms,
    42.7x, with byte-identical output and no regression on single-batch files.
    Two other ideas were measured and REJECTED: resize+memcpy is 1.8x slower
    because QVector zero-fills first, and CountRows() costs 20-73 ms, which is
    most of a single-batch load.
  - service.py's numbers() dispatched np.isfinite per element. On a 200k-row
    PCA that one line was 94% of the operation - 2.1 s of 2.3 s, against 0.1 s
    for the PCA. Vectorised: analysis.pca 663 -> 81 ms (8.2x), analysis.fft
    175 -> 17 ms (10.2x).

Duplication removed:

  - QtPlotBackend: the three-line "derive a spec as another engine" preamble
    was written out at 32 sites. One derivedAs() now, 50 lines lighter.
  - AppController: the active-dataset-plus-Arrow guard at three sites is
    requireActiveArrow(); ProjectWorkspace's folder guard at two is
    validFolder().
  - importer.py: the .mat and .h5 readers walked HDF5 with the same nine
    lines. One _hdf5_series().
  - surfaces.py: IDW and Modified Shepard chunked their k-NN queries
    identically. One _knn_blocks(); only the weighting differs now.
  - app/CMakeLists.txt listed the same 29 QML files twice.

Not yet compiled as a whole - the vcpkg install is still running - but every
translation unit compiles on its own against Qt and Arrow headers.
